# Portal notes, Access-2026-55984 resubmission (round 3), draft

## Abstract (plain text, 248 words)

This article evaluates the code security of URScript programs generated by large language models (LLMs) for an industrial robot. It does not evaluate motion safety: the task specification against which motion safety is checked is held invariant by design and never fails. Under ISO 10218-1:2025, the first edition to require cybersecurity where it affects safety, FACT (Formal Adversarial Code Testing) applies seven lexical security checks under seven prompt-injection strategies. The preregistered confirmatory study (Appendix A) covers three open-weight code models (16B to 34B) and 585 generations, reported from the second of two runs that agree on every preregistered test. First, the checks flag 89.2% to 98.8% of valid outputs, but a non-LLM comparator shows that this rate largely reflects the rule set and the prompt: the lower bound reduces to a missing tool-centre-point declaration that the task prompt never specified and that the reference translation also omits. Second, this saturation is a measurement hazard: naive scoring, and to a lesser degree the registered validity gate, lets invalid pseudo-code pass as safe, and the preregistered adversarial-uplift test has no power against it. Third, rule-checker feedback under whole-program regeneration does not remediate: no cell reaches zero violations. Exploratory single-repetition probes on frontier models (24B to 675B) show no remediation, and a benign edit removes an encoded speed cap in 0% to 70% of cells; these are signals for replication, not confirmed effects. Obtained in simulation and specific to URScript, the findings caution how generated control code is measured and patched.
